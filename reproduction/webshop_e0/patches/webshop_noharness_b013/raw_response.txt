The failure pattern is that the agent sometimes reaches a product detail page and tries to buy the item even though the item is not actually purchasable under the task constraints: either its current price is over the stated budget, or a required variant such as color, size, or material has not been selected yet. In WebShop this can look superficially valid because the Buy Now control is visible, but clicking it either buys the wrong item or fails to satisfy the instruction, so the harness should intervene at the moment the buy action is about to be taken.

The hook runs in on_before_action and only inspects click actions whose normalized value is Buy Now. It maps runtime predicates to two concrete blocks: if product_price_over_budget is true, it tells the agent to return to search or results and choose an in-budget item; if required_options_unselected is true, it tells the agent to choose the matching visible option first, using the task’s required color, size, and material fields when available to make the prompt specific. This keeps normal browsing and option selection behavior unchanged, but prevents an invalid purchase attempt from being submitted.
