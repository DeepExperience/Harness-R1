The failure pattern is that the agent sometimes reaches a product detail page and tries to buy the item even though the page still has a required variant choice unselected, such as color, size, material, flavor, count/pack, or similar option. In WebShop this can cause an invalid purchase attempt or prevent the model from completing the task, because the correct item is not actually chosen yet. The harness should intervene at the moment the agent attempts to click Buy Now, since that is the point where an otherwise recoverable option-selection mistake becomes a failed purchase action.

The hook runs in on_before_action and only inspects click actions whose normalized value is Buy Now. It maps runtime predicates to the needed behavior: if product_price_over_budget is true, it blocks the click and prompts the agent to return to search or results for an in-budget item. If required_options_unselected is true, it blocks Buy Now and gives a targeted prompt to choose the matching visible option before buying, with a fallback instruction to go back if no matching option is available. This keeps normal browsing and buying behavior unchanged except when the observable state shows the agent is about to submit a product that is either over budget or not fully configured according to the task requirements.
