The failure pattern is that the agent sometimes reaches a product detail page and tries to buy the item even though the page still has a required variant choice unselected, such as color, size, material, flavor, style, or a similar option. In WebShop this can turn an otherwise recoverable browsing step into a failed purchase: the model clicks Buy Now while the item is not actually configured to match the instruction, or it buys an item whose visible price is already over budget. The harness should intervene at the moment the Buy Now click is about to be taken, because that is the point where an avoidable invalid purchase can be stopped and the agent can be redirected to choose the missing option or return to search if the needed option is unavailable.

The hook runs in on_before_action and only inspects click actions whose normalized value is Buy Now. It maps runtime predicates to two blocks: if product_price_over_budget is true, it blocks the purchase and prompts the agent to go back and find an in-budget item; if required_options_unselected is true, it blocks Buy Now and tells the agent to select the matching visible option first, or use Back to Search when the required option is not offered. This keeps normal search and product inspection behavior unchanged, and only prevents the specific premature purchase action that the predicates show is not yet valid.
